# GENGEN AI Video

## Keep the Codex package current

When starting a GENGEN video task in Codex with local execution available, run
`node ../gengen-connect/scripts/update.mjs` from this skill's directory once before
using the tools. It checks the official GitHub release at most daily and uses the
Codex CLI to update an enabled, unpinned GENGEN install. Skip it in other hosts,
when the user has disabled updates, or when local execution is unavailable.
Respect host execution approvals; never retry a denied update through another
mechanism. Continue with the installed version on an unavailable check. Do not
narrate cached/no-change checks or interrupt a running generation to update.
An updated package loads according to the host's session refresh behavior; do not
claim that the current conversation has already reloaded its skills. If a new
local capability is needed immediately, explain that a new session may be needed.
For an explicit opt-out, run the helper with `--disable`; `--enable` opts back in.

## Start with the user's intent

Call `get_ai_workflow`. Collect only missing information through the host's native
question dialog when an appropriate question tool is available in the current mode.
In Codex, prefer `request_user_input_async`; use `request_user_input` only where
available and permitted. In Claude, use `AskUserQuestion` if exposed by the host.
Follow that tool's schema; do not invent a tool or switch modes just to ask.

For a new project, request the project name as free text. If the creative intent
is still unknown, ask one brief question about the idea or product to introduce;
use choices only for genuine alternatives, with the host's free-text option.
Reuse names, ideas, product details, and preferences the user already supplied.
Do not make the user complete a long setup questionnaire or ask them for internal
IDs, sourceHost, or technical configuration. Generate the request ID and derive
the source host yourself. Wait for required answers before creating the project;
dismissing a dialog is not consent to invent the missing answers. If no native
question tool is available, ask the same concise questions in conversation.

Native question dialogs collect text and choices, not file bytes. For materials,
use the host's attachment flow or the project's Materials tab. An idea alone is
sufficient. Product materials and a reference video are optional.
If GENGEN tools are unavailable or require account authorization in Codex, use
the bundled [gengen-connect skill](../gengen-connect/SKILL.md) to connect and
verify access before continuing. The user can also ask "Reconnect GENGEN" or
invoke `$gengen-connect`. Other hosts use their own OAuth connection flow.
Never ask for passwords, access tokens, or an API key in conversation.

Create a project with `create_ai_project`, retaining its request ID across retries.
Use `list_ai_projects` and `get_ai_project` to resume an existing project. A project
name is a display label; its ID identifies the saved project.

## Understand and write in this assistant

Use this host's native tools to inspect the supplied materials and discuss the
creative direction. Do not make a separate GENGEN LLM call for analysis or writing.
Do not claim to hear audio or view frames that this host did not expose.
Separate observed evidence from inference and record relevant limitations.
Never invent product facts, reference evidence, media IDs, or completed uploads.

Write the target script independently from the source video's shot count. Adapt
its creative idea to the actual product and objective. Use `save_ai_script` with
the current revision and the schema exposed by that tool. Only include `product`
or `reference` when present; otherwise use `idea`. Shot durations add up to the
target duration. List only supported product fact IDs and actually needed media
IDs. Read `get_ai_generation_options` for public video models and their supported
modes, durations, resolutions, aspect ratios, audio settings, and other controls.
Do not assume a fixed model or 720p output. Each run saves one playable MP4.
Speech and on-screen text are generation instructions;
review the output for fidelity before describing it as final.

## Review materials, then upload automatically

Collect all materials needed for the video, including originals supplied by the
user and outputs generated by this assistant. Reuse existing ready project media.
Use actual local files or the host's supported original-file export; a visible
attachment or generated-image preview alone does not prove access to its bytes.
Do not scan unrelated folders or include discarded generated variants.

Before reserving or uploading new files, follow
[the material review and upload procedure](references/material-upload.md).
Prepare a local manifest, then show **every selected material** in the conversation:
image previews, playable video/audio where supported (otherwise file links), and
a numbered list with filename, type, size, and intended use. Identify any original
that is unavailable. Explain that the selected files will be uploaded to this
GENGEN project's storage. Do not upload files just to make their previews visible.

Ask the user to confirm the displayed batch or specify changes using the host's
native question dialog when available; otherwise ask in conversation. Wait for
an explicit answer. A dismissed dialog, timeout, or prior request to make a video
is not approval of a new material list. Reuse explicit approval of an unchanged
reviewed batch. Adding, replacing, editing, or changing the use of a file requires
an updated review; keep already uploaded media instead of uploading it again.

After confirmation, automatically reserve, transfer, and complete every selected
local file using the bundled upload helper. Users do not need to select those files
again in Materials. Preserve the manifest, per-file request IDs, reservations, and
resumable state when retrying. Report partial failures accurately and retry only
unfinished work. Call `complete_ai_upload`, then check the project until each
selected media ID is ready; bind those IDs to the script and generation settings.
This approval covers material upload, not paid generation.

Only when original bytes cannot be accessed or exported, explain the specific
limitation and use the project's Materials chooser for those missing files. Never
substitute a thumbnail, transcript, fabricated URL, or re-encoded preview.
Preserve an optional reference video even when it is not used as a generation
reference. Source videos may be up to 300 seconds; references actually used in
video generation must satisfy the model's stricter limits. Text-only projects
need no upload or Asset Group. GENGEN manages provider asset IDs internally.

## Generate and review

1. Save the approved script. Read `get_ai_generation_options`, honor the user's
   model and parameter choices, and offer only supported controls and material slots.
   The project panel and website also let the user edit these settings directly.
   Call `prepare_ai_generation` for the exact script revision with `model`, `mode`,
   `controls`, and `mediaBindings` (project media IDs, never remote URLs or Asset IDs).
   An empty `mediaBindings` explicitly excludes materials. Omitted bindings inherit
   the script's references. Changing duration scales the run's shot timeline;
   revise the script instead when the pacing or content needs substantive changes.
2. Use the existing host confirmation message to show the script revision, model,
   output settings, and selected materials. Ask the user to confirm generation.
   Do not add a card, estimated amount, or billing notice to this confirmation.
   If the user asks about pricing or charges, answer accurately using the estimate;
   generation still consumes account balance based on final usage. Preserve the
   host's own action approvals and all billing metadata.
3. Copy the returned `model`, `mode`, `controls`, and `mediaBindings` into
   `submit_ai_generation`, with `approvedEstimateUsd` copied from `estimatedChargeUsd` and a stable request ID.
   A change to any setting or material requires a fresh estimate and approval.
   Reuse the same request ID and exact settings after a timeout. A new ID creates
   another paid run. Never reuse an approved quote for different settings.
4. Call `get_ai_project` to show progress and inline playback where the host supports
   MCP Apps. GENGEN continues in the cloud after the conversation closes. Never
   claim that this assistant itself is monitoring after the turn ends.
5. A `reconciliation` status needs recovery of the existing task. Do not automatically
   submit a replacement or tell the user the original task failed.
6. Present completed videos for review. Call `select_ai_video` when the user chooses
   a final result. Script changes create another version and do not change a
   submitted run. If inline apps are unavailable, provide the saved project link
   and accurately explain that this host has not shown inline playback.

This package needs the deployed MCP endpoint, approved OAuth client, database
upgrades, and a private worker. Package installation alone does not provision them.
